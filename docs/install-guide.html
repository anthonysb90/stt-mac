Aloud · push-to-talk dictation

Installing Aloud

Start to finish on one Mac. Pick your machine below and the steps that don’t apply to it will disappear — everything left on the page is for you.

This Mac is
0 of 10

In a hurry? Once the code is on this Mac (step 4), one command does everything else — picks the right Python, installs the engine and model for your architecture, builds the app, and puts it in /Applications. It stops at the two permissions, because nothing can grant those for you.

Terminal — ~/Developer/aloud
$ ./scripts/install.sh

The steps below are the same thing, one at a time, for when you want to see what’s happening or something goes wrong.

Terminal — not sure which Mac you’re on?
$ uname -m

arm64 is Apple Silicon. x86_64 is Intel.

You need

  • macOS 11 (Big Sur) or newer
  • Xcode Command Line Tools — ~2 GB, free
  • Homebrew
  • Python 3.10+ Silicon / 3.9+ Intel
  • ~3 GB free disk Silicon / ~1 GB Intel

You don’t need

  • Xcode
  • An Apple Developer account
  • Any paid service
  • An internet connection after setup

“Command Line Tools” is not Xcode. Xcode is the ~10 GB IDE from the App Store — you never need it. The Command Line Tools are a separate free download that ships the compiler and codesign. Every route to a working Mac app needs those, including this one.

01

Command Line Tools

Check whether you already have them. If the first command prints a path, skip to step 2.

Terminal
$ xcode-select -p

If that errors, install them. A system dialog appears — click Install, accept the licence, and wait 5–10 minutes.

Terminal
$ xcode-select --install
02

Homebrew

Run which brew first. If it prints a path, skip ahead.

Terminal
$ /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
Apple Silicon Read what it prints at the end

It asks you to add Homebrew to your PATH. Run these, or brew won’t be found in new terminal windows.

Terminal
$ echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
$ eval "$(/opt/homebrew/bin/brew shellenv)"
Intel Nothing extra

Homebrew installs to /usr/local, which is already on your PATH.

03

Python

Terminal
$ python3 --version
Apple Silicon Needs 3.10 or newer

Parakeet requires it, and macOS ships 3.9. If you saw 3.9.x, install a newer one and note the path — you’ll pass it to the next step.

Terminal
$ brew install python@3.12
$ $(brew --prefix)/bin/python3.12 --version

If python3 --version already said 3.10 or higher, there’s nothing to do here.

Intel 3.9 is fine

Whatever macOS gave you will work. Nothing to do.

04

Get the code

Put it somewhere permanent — the app runs against this folder, so moving or deleting it later breaks the app.

Terminal
$ mkdir -p ~/Developer && cd ~/Developer
$ git clone https://github.com/anthonysb90/stt-mac.git aloud
$ cd aloud
$ git checkout claude/whispr-dictation-app-glvd1v

If git asks you to log in, stop. On a public repo it never should. Being asked means GitHub answered “404” to an anonymous request — which it does both for a repo that doesn’t exist and for one that’s private, because it deliberately doesn’t distinguish the two. So the repo is still private, or the URL has a typo.

Fastest way past it, with no terminal login at all: download the ZIP. Nothing here needs git history.

  1. Open the branch in a browser you’re already signed into GitHub with: github.com/anthonysb90/stt-mac/tree/claude/whispr-dictation-app-glvd1v
  2. Green Code button → Download ZIP.
Terminal
$ mkdir -p ~/Developer
$ cd ~/Downloads
$ unzip stt-mac-claude-whispr-dictation-app-glvd1v.zip
$ mv stt-mac-claude-whispr-dictation-app-glvd1v ~/Developer/aloud
$ cd ~/Developer/aloud

Every step from here on is identical. The only thing you give up is git pull for updates — download a fresh ZIP instead.

05

Bootstrap

One script: virtualenv, the right engine for this architecture, and the model. The model download is the slow part — let it finish.

Intel Run it plain
Terminal — ~/Developer/aloud
$ ./scripts/bootstrap.sh
Apple Silicon Point it at the right Python

If step 3 made you install Python 3.12, use the first command. If python3 --version already said 3.10+, the second is enough.

Terminal — ~/Developer/aloud
$ PYTHON_BIN=$(brew --prefix)/bin/python3.12 ./scripts/bootstrap.sh
# …or, if your python3 is already 3.10+:
$ ./scripts/bootstrap.sh
What it doesApple SiliconIntel
Installs the engineParakeet on MLXfaster-whisper, CPU
Installs ffmpegYes — Parakeet decodes with itNot needed
Downloads the model~2.4 GB~150 MB

It refuses early, with the fix, if your Python is too old — so a failure here costs seconds, not a half-finished install.

06

Check it worked

Do this before building. It’s much easier to fix a missing model now than to wonder later why nothing happens.

Terminal — ~/Developer/aloud
$ make doctor

You want your architecture, ok beside the engine marked (active), and your microphone listed. A -- on the active engine is a problem — the troubleshooting section at the bottom covers the usual causes.

07

Make a signing certificate

Optional, two minutes, and worth doing before you install rather than after.

Why bother. Without one, the app is ad-hoc signed and gets a brand-new identity every time you build it. macOS treats each rebuild as a different app and makes you grant Accessibility again from scratch. With one, the permission you grant in step 9 survives every future rebuild.

  1. Open Keychain Access (Spotlight it).
  2. Menu bar: Keychain Access→Certificate Assistant→Create a Certificate…
  3. Name it Aloud Dev. Identity Type: Self Signed Root. Certificate Type: Code Signing.
  4. Click Create, then Done.

Then make your shell use it, so you never have to remember:

Terminal
$ echo 'export CODESIGN_IDENTITY="Aloud Dev"' >> ~/.zshrc
$ source ~/.zshrc

Skipping this is fine — everything still works. You’ll just re-grant Accessibility after each rebuild.

08

Build and install

Builds Aloud.app and copies it into /Applications. It’s a normal Mac app from here on — Dock icon, application menu, a window you can close without quitting.

Terminal — ~/Developer/aloud
$ make install

The build starts the bundle once and fails loudly if it can’t — so a broken build tells you why here, not as a dialog later.

The app runs against ~/Developer/aloud/.venv. Keep that folder where it is — moving or deleting it breaks the app. That’s deliberate: the engines are MLX (with its Metal shader libraries) or CTranslate2, and py2app has no recipe for bundling either. make app-standalone attempts a self-contained bundle if you want to try, but expect it to fail.

Open it from Launchpad or Spotlight. It will appear in the Dock and in your menu bar as ◌.

09

Grant the two permissions

macOS will not let an app grant itself either of these. This is the step people get stuck on, so it’s worth doing carefully.

Microphone — it asks you

Open Aloud and press Start Dictation once. macOS asks — click Allow.

If you miss the prompt: System Settings→Privacy & Security→Microphone and switch Aloud on.

Accessibility — you must add it by hand

Aloud needs this to see the hotkey system-wide and to paste into other apps. There is no API for an app to grant itself this.

  1. System Settings→Privacy & Security→Accessibility
  2. Click the + button.
  3. Go to Applications, select Aloud, click Open.
  4. Make sure the switch beside it is on.
  5. Quit Aloud completely (⌘Q) and open it again.

That last line is not optional — the permission is only read at launch.

10

Dictate something

  1. Open anything you can type in — Notes, Mail, a browser.
  2. Click into a text field.
  3. Hold Right Option, say a sentence, release.

The menu bar glyph goes ◌ → ● while recording → ◍ while transcribing, and your text lands where the cursor is.

Why Right Option and not Fn? Right Option does nothing on its own, so there’s nothing to collide with. Fn is the more Wispr-like choice, but macOS gives it a built-in action — if you want it, first set System Settings→Keyboard→Press 🌐 key to→Do Nothing, or it opens the emoji picker every time you dictate. Change the key in Aloud’s Settings (⌘,).

The first one is slow. That’s the model loading, once. Every dictation after it is fast — the model stays in memory.

Optional extras

None of this is needed to dictate. Come back to it later.

Use Deepgram instead of the local engine

Deepgram does transcription and cleanup in one call — punctuation, capitalisation, filler removal, spoken punctuation (“period”, “new line”), numbers as digits. Its keyterm prompting is also a stronger way to push your Dictionary words at the model than a Whisper prompt.

It uploads your audio, which is why it is never chosen automatically.

Get a key from deepgram.com (there’s a free tier), then store it:

Terminal — ~/Developer/aloud
$ .venv/bin/python -m aloud key deepgram

Then in Aloud’s Settings (⌘,), set Engine to Deepgram (cloud). To go back, set it to Automatic.

Don’t just export the key in .zshrc. An app launched from the Dock doesn’t inherit your shell environment, so the key would work in Terminal and silently fail in the app. That’s exactly what aloud key exists to avoid — it writes to a file the app can actually read.

Start Aloud at login

System Settings→General→Login Items→Open at Login→+ and choose Aloud.

Install the offline fallback engine

whisper.cpp needs no Python ML stack at all, which makes it the thing that still works if the main engine breaks. It’s slower — it reloads the model on every dictation — so it’s opt-in.

Terminal — ~/Developer/aloud
$ ./scripts/bootstrap.sh --with-whisper-cpp
Work on the code

make dev-app builds a bundle that links back to your checkout, so edits take effect without rebuilding. Use that while changing things, and make install for the real one. Don’t keep a dev build in /Applications — it breaks if you move the checkout.

Terminal — ~/Developer/aloud
$ make test      # run the test suite
$ make run       # run from the terminal
$ make warm      # pre-load the model

When something goes wrong

Run make doctor from ~/Developer/aloud first — it answers most of these.

The hotkey does nothing

Accessibility isn’t granted, or it was granted to a previous build. Redo step 9 — including the quit and reopen.

After an ad-hoc-signed rebuild you must remove Aloud from the Accessibility list with the − button and add it again. Toggling the switch off and on is not enough, because macOS sees a different app. Step 7’s certificate prevents this.

“Launch error — see the py2app website for debugging launch issues”

That dialog is a Python traceback that got thrown away. This prints the real one, by running the app’s binary directly in your terminal:

Terminal — ~/Developer/aloud
$ make diagnose

Send that output on and the fix is usually immediate.

Is it the bundle, or the code?

make run runs the same app straight from the checkout, skipping the bundle entirely. If that works and the installed app doesn’t, it’s a packaging problem. If both fail the same way, it’s the code.

Terminal — ~/Developer/aloud
$ make run
Nothing happens at all — no menu bar icon

Run make diagnose first. If that starts cleanly, check the log:

Terminal
$ tail -f ~/Library/Logs/Aloud/aloud.log
“parakeet-mlx is not installed” Silicon

Almost always Python: it needs 3.10+ and macOS ships 3.9. Redo step 3, then re-run bootstrap with PYTHON_BIN= pointing at the newer one.

“ffmpeg not found” Silicon

Parakeet decodes audio through it.

Terminal
$ brew install ffmpeg
It’s slow on every dictation Intel

Expected — there’s no GPU path on Intel. In Settings (⌘,), set the model to tiny.en, or switch this Mac to Deepgram.

Text appeared in the wrong app

Aloud pastes into whatever has focus when transcription finishes. Don’t click away while the glyph is ◍.

My clipboard got replaced

It’s put back about a second after pasting. If something else writes to the clipboard inside that window, Aloud leaves it alone rather than overwriting what you copied.

A word keeps coming out wrong

That’s what the Dictionary is for. Press ⌘2 in Aloud, then Add Word for a name it should know, or Add Correction for a phrase it always mishears. If an entry looks like it would rewrite an everyday word, the editor warns you before you can save it.

Updating later
Terminal — ~/Developer/aloud
$ git pull
$ ./scripts/bootstrap.sh
$ make install

With the step 7 certificate, permissions carry over. Without it, redo step 9’s Accessibility part.

Uninstalling
Terminal
$ rm -rf /Applications/Aloud.app
$ rm -rf ~/Library/Application\ Support/Aloud
$ rm -rf ~/Library/Logs/Aloud ~/Library/Caches/Aloud
$ rm -rf ~/Developer/aloud

Also remove Aloud from Privacy & Security → Accessibility and → Microphone. Models live in ~/.cache/huggingface; delete that too if nothing else needs it.
